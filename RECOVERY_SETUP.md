# Recovery V2 — install, resume, and next-agent handoff

**This is an iteration of the previous Skill, not a replacement.** The archive retains the entire V1 `.agents/skills/scientific-law-autopilot/` with both original development/supervision references, V1 orchestration, and CI config. New additions are `scientific-law-recovery/SKILL.md`, issue ledger and recovery tool.

## Installation

First commit/back up existing local changes. Copy/extract the V2 ZIP into the root of a **writable clone** of `PWTnbplus/exp_from_llm_to_agent`. Do not delete existing files: inspect conflicts and merge by evidence. Use a feature branch `autopilot/scientific-law-discovery`, not `main`. **The ZIP intentionally contains no `docs/state/issues.json`, `gates.json` or generated state reports**, so an existing issue ledger cannot be reset by this distribution. These files are generated by bootstrap, and any existing files are preserved. If the repository has modified source code that would be overwritten by the installer, review and merge those differences before extraction. Requires Python 3.10+, Git, an authenticated Codex CLI and Git credentials with repo write access. A prompt cannot grant permissions or keep a host running.

```bash
python scripts/recovery_state.py bootstrap
python scripts/recovery_state.py status
python scripts/recovery_state.py next
python -m unittest discover -s tests -p 'test_recovery_state.py' -v
python scripts/autopilot.py --resume-only --cycles 12 --repairs 2 --test-cmd "python -m pytest -q"
```

For the **next agent**: start at `docs/state/HANDOFF.md` and `docs/state/issues.json`. Do not rerun initial project scaffolding/benchmark audit if documented as verified in `completed_work` with reproducible commands and pinned commits. Fix the highest-priority unresolved issue, gather independent evidence, update the ledger and reports, then commit/push. If no outstanding issue exists, identify the next genuinely missing hard gate; do not invent work.

## Useful issue commands

```bash
python scripts/recovery_state.py bootstrap
python scripts/recovery_state.py next
python scripts/recovery_state.py status
python scripts/recovery_state.py report
python scripts/recovery_state.py start --id ISSUE-xxxxxxxxxxxx --reason "Reproduced failing isolation test"
python scripts/recovery_state.py block --id ISSUE-xxxxxxxxxxxx --reason "Remote write permission missing; grant repository write access"
python scripts/recovery_state.py claim-fixed --id ISSUE-xxxxxxxxxxxx --reason "Patch added; awaiting independent review"
python scripts/recovery_state.py milestone --name "NewtonBench Adapter" --evidence "Adapter integration test from pinned SHA passes" --command-run "python -m pytest tests/test_newtonbench_adapter.py -q" --commit "<verified commit SHA>"
```

**Manual `verify` is deliberately disabled.** VERIFIED is granted only by a structured independent-review resolution accompanied by a successful host-executed test. The reviewer must cite actual code and test evidence. A simple passing suite without issue-specific evidence is not proof.

## Canonical state, file ownership and safety

- `docs/state/issues.json`: durable, machine-readable issue status; commit after each cycle.
- `docs/state/UNRESOLVED_REPORT.md`: human report, generated from ledger.
- `docs/state/HANDOFF.md`: next-agent entrypoint, generated from ledger.
- `docs/audits/cycle-*/audit.json`: immutable-ish historical review evidence; never prune failures for optics.
- `docs/state/gates.json`: optional gate evidence matrix; do not mark PASS without real evidence.

Do not edit the generated report by hand to change issue status. Edit the ledger through the tool/review workflow, then regenerate reports. Do not hand-edit issues to mark VERIFIED.

If GitHub push fails, local commits remain on disk but cannot be represented as remotely delivered. Stop and report the exact blocker. No force pushes, no main merges, no paid scientific API batches without explicit permission and limits.

## Operational boundaries

An issue ledger prevents redundant tasks only to the extent previous work and tests were recorded accurately. The review agent still needs to audit genuinely suspect completed work when new evidence appears. "Auto-resume" works while the trusted Codex process is invoked and credentials/tools remain available. For recurring unattended execution, deploy it on an authorized scheduled runner with runtime and spend limits.

## Gate evidence

To mark a gate PASS, provide a real passing Python test command and written evidence; the tool executes the command, never accepts a naked claim:

```bash
python scripts/recovery_state.py gate-pass --gate G1 --evidence "Frozen-plan observation-swap test passes; src/runners/llm_only.py" --command-run "python -m pytest -q tests/test_llm_isolation.py" --commit "<actual SHA>"
```

Commands are executed locally from the repository and should only run trusted project tests. Gates that are not explicitly checked remain NOT TESTED.
